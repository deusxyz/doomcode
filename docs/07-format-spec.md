# Автоформатирование (рамки v1, п. 5)

Обновлено 2026-10-08. Реализовано в Edwood `main`: `fmtfile.go` (таблица правил, файл, команда `Fmt`), `format.go` (запуск фильтра, замена текста), вызов из `put` в `exec.go`.

## 1. Что делает

Перед записью файла командой `Put` (из тега, с клавиатуры `Ctrl-S`, через `Putall` и через `ctl` «put») тело окна прогоняется через внешний фильтр, выбранный по суффиксу или имени файла. Фильтр читает текст со стандартного ввода и печатает отформатированный на стандартный вывод; рабочий каталог — каталог окна. Если вывод отличается, текст заменяется, затем выполняется запись. Это замена `acmego -f` и `|gofmt`: один шаг вместо двух и без лишнего окна.

- Фильтр с ненулевым кодом возврата (синтаксическая ошибка) или не уложившийся в 10 с: текст не трогается, сообщение и stderr фильтра — в `+Errors`, запись выполняется как есть. Форматирование никогда не блокирует Put.
- Сообщения фильтра пригодны для перехода: имя стандартного ввода (`<standard input>` у gofmt, `<stdin>` у rustfmt и clang-format) заменяется полным путём файла окна, поэтому `путь:39:1: …` в `+Errors` открывается по B3 или Ctrl-O на строке 39. Заголовок одной строкой: `Fmt: путь: gofmt failed; text left unchanged`; код возврата не печатается, причина пишется только когда фильтр не запустился или не уложился во время.

```
Fmt: /…/acmefs.go: gofmt failed; text left unchanged
/…/acmefs.go:39:1: expected declaration, found fun
```
- Замена текста минимальна: общий префикс и суффикс старого и нового текста не трогаются, заменяется только середина. Поэтому выделение, позиция прокрутки и стили (`style`) вне изменённого места сохраняются. Позиция строго внутри изменённого места переходит в его конец, поэтому выделение, накрывавшее изменённый текст, накрывает новый. Замена — одна точка отмены (`Undo` возвращает неформатированный текст).
- Окна-каталоги и окна без правила не форматируются.

## 2. Файл `fmt`

`$EDWOOD_FMT`, иначе `$XDG_CONFIG_HOME/edwood/fmt`, иначе `~/.config/edwood/fmt`. Накладывается на правила по умолчанию, поэтому в нём только изменения.

```
# суффикс (с точкой) или точное имя файла, затем команда и аргументы
.go   gofmt -s
.rs   rustfmt --emit stdout
.py   black -q -
.json jq .
Makefile -        # одиночный «-» снимает правило
put off           # не форматировать при Put; Fmt работает по-прежнему
```

Точное имя файла (`go.mod`, `Makefile`) имеет приоритет над суффиксом. Суффиксы сравниваются без учёта регистра. `#` — комментарий до конца строки.

**По умолчанию** одно правило: `.go gofmt` (gofmt детерминирован и стандартен для Go; остальные форматтеры ставят по вкусу). `put on` по умолчанию.

## 3. Команда `Fmt`

| Команда | Действие |
|---|---|
| `Fmt` | отформатировать тело текущего окна его правилом сейчас (без записи) |
| `Fmt cmd args…` | отформатировать разово указанным фильтром; аргументы делятся по пробелам, кавычки не разбираются |
| `Fmt reload` | перечитать файл `fmt` поверх правил по умолчанию |
| `Fmt rules` | показать действующие правила и путь к файлу |
| `Fmt file` | путь к файлу |

Файл читается при запуске (ошибки — в лог) и по `Fmt reload`.

## 4. Решения

- **Где конфиг** (вопрос из `02` §5): отдельный файл `fmt` рядом с `keys` и `theme`, тот же поиск пути и тот же стиль «только изменения поверх умолчаний».
- **Синхронно внутри Put**, а не через `+Errors` и отдельное окно, как у `acmego`: иначе нельзя гарантировать, что на диск уходит отформатированный текст. Ограничение 10 с защищает от зависшего фильтра.
- **Не через `rc`**: команда запускается напрямую (`exec.Command`), без оболочки, поэтому кавычки и переменные в строке правила не раскрываются. Нужен сложный конвейер — оберните его в скрипт.
- **Взаимодействие с `acme-lsp`**: acme-lsp тоже умеет форматировать при Put через `event`. Оба могут работать одновременно: результат идемпотентен. Если это мешает, `put off` в файле `fmt`.
