# План ручной проверки

Обновлено 2026-10-08. Что ещё не проверено руками. Отмечайте `[x]` по мере проверки; замечания пишите прямо под пунктом.

## Подготовка

- [ ] Пересобрать и запустить: `./build.sh`, затем `./run.sh <файлы>`. Старый запущенный редактор (`bin/edwood`) закрыть: программа теперь называется `bin/doomcode`, пространство имён `/tmp/ns.doomcode`, конфиги в `~/.config/doomcode`.
- [ ] В теге любого окна выполнить `Syn` (подсветка и ошибки разбора).
- [ ] Для пунктов про LSP запустить acme-lsp в том же пространстве имён. Из тега окна проекта, B2 по строке:
  ```
  acme-lsp -server '\.go$:gopls' -rootdir /путь/к/проекту
  ```
  затем `Diag` в теге. Команда `L` должна находиться в PATH: она лежит в `~/go/bin`, `run.sh` добавляет этот каталог.

## Клавиши для команд acme-lsp (`docs/03` §5.4)

На Mac F-клавиши нажимаются с fn, если в настройках клавиатуры не включены стандартные функциональные клавиши.

- [ ] Курсор на имени функции, **F12**: открывается окно с определением, курсор на нём.
- [ ] То же через **Ctrl-B d**.
- [ ] Курсор на имени, **Ctrl-B r**: список ссылок появляется в `+Errors`, по строке из него работает Ctrl-O.
- [ ] Курсор на имени, **F2**: в теге появляется `L rn `, ввод переходит в тег. Набрать новое имя, **Esc**, **Ctrl-E**: имя переименовано во всех файлах.
- [ ] То же через **Ctrl-B R**.
- [ ] Начать набирать имя, **Option+Esc**: единственный вариант вставляется, несколько вариантов выводятся в `+Errors`.
- [ ] **Ctrl-B h** на имени: подсказка в `+Errors`.
- [ ] **Ctrl-B i** на интерфейсе: реализации в `+Errors`.
- [ ] **Ctrl-B k** внутри скобок вызова: сигнатура в `+Errors`.
- [ ] Без запущенного acme-lsp **F12**: понятное сообщение в `+Errors`, редактор не зависает.
- [ ] Своя привязка: в `~/.config/doomcode/keys` строка `F5 run go test ./...`, затем `Keys reload`. **F5** в окне Go-пакета запускает тесты, вывод в `+Errors`.
- [ ] `Keys` показывает новые привязки, `Keys actions` перечисляет `run <command>` и `tag <text>`.

## Диагностика `Diag` (`docs/05` §8)

- [ ] Сделать ошибку типа (`var x int = "s"`), **Ctrl-S**: место подчёркнуто красным на розовом.
- [ ] Исправить, **Ctrl-S**: подчёркивание исчезает.
- [ ] Набрать текст выше ошибки: подчёркивание едет вместе с текстом.
- [ ] Подсветка синтаксиса и подчёркивания `Diag` не стирают друг друга.

## Ошибки разбора в `Syn` (`docs/05` §8)

- [ ] Сломать ключевое слово (`func` → `fun`): подчёркнуто объявление; вернуть букву: подчёркивание уходит.
- [ ] Убрать `)` в вызове: подчёркнут токен перед ней.
- [ ] Набор новой строки кода не заставляет экран мигать подчёркиваниями.
- [ ] Записать, что именно хочется «допилить» (лишние подчёркивания, не то место, мешает при наборе).

## `%f` в правилах форматирования (`docs/07` §2)

Нужен установленный prettier (`npm i -g prettier`); без него пункт пропустить.

- [ ] В `~/.config/doomcode/fmt` строка `.ts prettier --stdin-filepath %f`, затем `Fmt reload`.
- [ ] Испортить отступы в `.ts`, **Ctrl-S**: текст отформатирован, файл записан.
- [ ] Синтаксическая ошибка в `.ts`, **Ctrl-S**: сообщение в `+Errors` с путём к файлу, файл записан как есть.
