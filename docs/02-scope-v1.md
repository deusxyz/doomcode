# Рамки версии 1 и оценка реализуемости

Решение от 2026-10-04: совместимость с расширениями VS Code вынесена за рамки. Цель — Acme, доработанный в пяти направлениях:

1. нормальные клавиатурные комбинации;
2. удобное управление курсором по тексту;
3. нормальные копирование, вырезание, вставка;
4. подсветка синтаксиса;
5. автоформатирование.

LSP остаётся «через acme-lsp», как сейчас; встроенная поддержка — кандидат на версию 2.

## Кандидаты на базу

| Совместимость с клиентами acme(4) | эталон | заявлена как drop-in, проверяется тестами и 9ptest | надо писать и проверять |
| Платформы | Unix/macOS через devdraw | Unix/macOS через plan9port devdraw; Windows через duitdraw (с оговорками) | — |
| Шрифты | subfont Plan 9, TTF через fontsrv | то же, плюс TTF и Go Font напрямую через duitdraw | — |
| Что уже есть из списка | Cmd-C/X/V/Z на macOS | Ctrl-C/X/V/Z на всех платформах, пакет `theme` с палитрой (в разработке) | — |

Рекомендация: **форк Edwood** (или ветка с прицелом на upstream). Писать с нуля не оправдано: 90 % ценности Acme в поведении, которое уже реализовано и покрыто тестами, а все пять пунктов — локальные доработки.

Почему не Anvil: подсветка и клавиатура там уже есть, но нет файлового API acme(4), а значит теряются `win`, `acme-lsp`, `acmego`, `Watch` и вся экосистема. Это нарушение главного принципа, а не доработка.

## Оценка по пунктам (на коде Edwood)

### 1–2. Клавиатура и курсор

Вся обработка в одной функции `Text.Type` (text.go, строки ~840–1050). Сегодня: стрелки, PgUp/PgDn, Home/End, `^A ^E ^H ^U ^W ^F`, Del, Esc, Ctrl/Cmd-C/X/V/Z.

Добавить:

- Shift + стрелки/Home/End/PgUp/PgDn — расширение выделения (у Text есть q0/q1, нужно помнить «якорь»).
- Ctrl/Alt + ←/→ — по словам; Ctrl + ↑/↓ — по абзацам или скролл строки.
- Ctrl-Backspace/Ctrl-Del — удалить слово (сейчас только ^W).
- Ctrl-A — выделить всё (конфликт с ^A «начало строки» — решить: Emacs-привычка или CUA).
- Клавиатурный B2: выполнить слово под курсором или выделение (`execute(t, q0, q1, false, nil)` уже есть в exec.go). Кандидат: Ctrl-Enter, как в Anvil.
- Клавиатурный B3: `look3(t, q0, q1, false)` уже есть в look.go. Кандидат: Alt-Enter или Ctrl-Shift-Enter.
- Перенос фокуса между окнами и колонками с клавиатуры: нужен явный «текущий текст» вместо «под мышью». Режим `-b` (bartflag: ввод идёт в последнее кликнутое окно) уже есть, это основа. Новое: Ctrl-Tab / Ctrl-стрелки по дереву Row → Column → Window, плюс «перенести мышь к фокусу», чтобы не ломать мышиную модель.
- Ctrl-S = Put, Ctrl-Z/Shift-Z уже есть, Ctrl-F = Look по выделению, Ctrl-N = New, Ctrl-W = Del (конфликт с ^W).
- Таблица привязок — в конфиг, а не в код: это же пункт roadmap Edwood.

Объём: малый. Главная работа — продумать таблицу, а не написать код.

### 3. Копирование, вырезание, вставка

В Edwood уже есть Ctrl-C/X/V на всех платформах и синхронизация snarf с системным буфером обмена. Остаётся: вставка без выделения в позицию курсора ведёт себя как в Acme (заменяет выделение) — проверить, добавить Ctrl-Shift-V «вставить как текст без автоотступа», история буфера — опционально. Фактически пункт закрыт.

### 4. Подсветка синтаксиса

Единственный архитектурно значимый пункт. Как устроен `frame`: текст разбит на `frbox` (пробег рун одного вида; границы — табуляции и переводы строк), и `drawtext` рисует каждый box одним цветом `text` и одним шрифтом `f.font`:

```go
for _, b := range f.box {
    pt = f.cklinewrap(pt, b)
    if !f.noredraw && b.Nrune >= 0 {
        f.background.Bytes(pt, text, image.Point{}, f.font, b.Ptr)
    }
    pt.X += b.Wid
}
```

Минимальное изменение: добавить в `frbox` индекс стиля, резать box'ы ещё и на границах стилей (механизм разрезания уже есть для табуляций), в `drawtext` выбирать цвет/шрифт по стилю. Выделение (`DrawSel`) и тик уже рисуются поверх, их трогать не надо. Шрифт на окно по-прежнему один, стили — цвет, фон, возможно жирность/курсив из того же семейства.

Второй слой: откуда берутся стили. Нужна структура «отрезки стилей» на Text, которая сдвигается при вставках/удалениях (как сейчас сдвигаются адреса в `addr`). Два источника:

- **Внешний процесс по-акмовски**: файл `N/style` в acme(4), куда программа `Syn` пишет отрезки `q0 q1 style`, подписавшись на `log`/`event`. Плюсы: ядро не знает о языках, подсветчик меняется без пересборки, работает любой инструмент (tree-sitter, TextMate-грамматики из `.vsix`, простой regex). Минусы: задержка на больших файлах, мерцание при наборе, если не делать инкрементально.
- **Встроенный tree-sitter** (go-tree-sitter, cgo): мгновенно и инкрементально, но ядро обрастает грамматиками и cgo.

Рекомендация: сначала файл `style` в FS-API плюс поставляемая программа `Syn` на tree-sitter. Если задержка окажется неприемлемой, встроить tree-sitter внутрь, сохранив `style` как внешний интерфейс. Тот же файл `style` потом даст inline-диагностику LSP, подчёркивание ошибок и git-разметку без новых концепций.

Объём: средний. Изменения в `frame` (с тестами), новая структура отрезков в `Text`, новый файл в `xfid.go`, программа `Syn`.

### 5. Автоформатирование

Уже решено снаружи: `acmego -f` (gofmt, rustfmt, yapf), `acme-lsp` форматирует при `Put`, `|gofmt` через пайп. Встроенный вариант: таблица «суффикс → команда-фильтр» в конфиге и вызов перед записью в `put` (exec.go) с сохранением выделения. Объём: малый. Вопрос только в том, где конфиг.

## Инварианты, которые не трогаем

1. Любой текст на экране редактируем и исполняем (B2) или «ищем» (B3); клавиатура даёт те же три действия, а не новые.
2. Файловый API acme(4) совместим: все существующие клиенты работают без изменений. Новые файлы (`style`) только добавляются.
3. Контекст команды — каталог тега, вывод — в `+Errors`.
4. Тайлинг колонками, автоматическое размещение, никаких вкладок, меню и диалогов.
5. Мышиная модель Acme остаётся полностью рабочей; клавиатура — равноправная альтернатива, не замена.
6. Стили — слой поверх текста, не часть текста: `body` по-прежнему отдаёт чистый текст.

## Решения от 2026-10-04

1. **Клавиатурная схема — CUA** (Ctrl-C/X/V/Z/Y, Ctrl-A выделить всё, Ctrl-F поиск, Ctrl-S = Put, Shift+движение = выделение). Emacs-привычки ^A/^E/^W уступают место стандарту; `Esc` оставляем акмовским (выделить набранное). Копирование и вырезание — раздельные операции: Ctrl-C = Snarf без удаления, Ctrl-X = Cut. Аккорды мыши остаются как есть.
2. **Полная работа с клавиатуры нужна.** Навигация между окнами и колонками — по образцу tmux / Windows Terminal: префикс + стрелки (кандидат префикса Ctrl-B или Ctrl-Space, уточнить), плюс префикс + цифра/буква для прямого перехода, префикс + `n/p` для нового/предыдущего окна. Фокус явный (режим `-b` как основа), мышь переносится к фокусу.
3. **Подсветка — внешним процессом через файл `style`** в acme(4). **LSP** нужен: сначала через `acme-lsp` поверх совместимого API, затем inline-диагностика через тот же `style`.
4. **Платформа:** сейчас macOS, Linux позже обязателен. База Edwood это покрывает: на обеих платформах через plan9port devdraw, на Linux есть и чисто Go-вариант (duitdraw).

**База подтверждена:** Edwood v0.4.0-64-gf6f9012 собран на этой машине (`edwood/bin/edwood`), все 11 тестовых пакетов прошли, 9P-сервис работает (`9p ls acme`, запись в `acme/new/body`). Edwood и plan9port acme используют одно имя сервиса `acme`; для параллельного запуска Edwood стартует с `NAMESPACE=/tmp/ns.edwood`.
