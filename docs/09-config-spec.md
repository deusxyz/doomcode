# Настройка: конфиг, системная тема, мягкие палитры (идеи 2, 3 и 6)

Черновик спецификации от 2026-10-08. Идеи из `docs/08` §2, §3, §6, замечание пользователя: «непонятно, как настраивать редактор». Текущее устройство описано в `docs/configuration.md`. Решения пользователя отмечены «**Решено**», мои предложения — «**Предлагаю**», вопросы — в §7.

## 1. Цель

Человек, впервые запустивший doomcode, должен за минуту понять, где настройки, увидеть все значения по умолчанию и поменять нужное, не читая код. Редактор с первого запуска выглядит прилично: тема как у системы, читаемый шрифт, спокойные цвета.

## 2. Проверка на дублирование (`docs/04` §3)

- **acme, Edwood** — настроек почти нет: флаги запуска и переменные окружения. Конфиг-файлов, команды «открыть настройки», системной темы нет. Повторять нечего.
- **acme-lsp** — свой конфиг (`acme-lsp.toml`) только для языковых серверов; пересечений нет.
- **Темы**: готовые палитры с открытыми лицензиями (Catppuccin, Nord, Gruvbox, Solarized) берём как образец цветов, а не пишем с нуля (§6).

## 3. Порядок значений

**Решено (пользователь):** значение берётся в таком порядке, первое найденное побеждает:

1. **флаг запуска** (`-f`, `-F`, `-palette`, `-W`, …) — если передан;
2. **файл настроек** — если файл есть и значение в нём задано;
3. **значение по умолчанию в коде**.

То есть настройки из конфига и умолчания можно «перегрузить» аргументами запуска. Так уже работают `-palette` и строка `palette` в файле `theme`; правило распространяется на всё новое, начиная со шрифтов.

Технически: флаги без явного значения не должны затирать конфиг — `flag.Visit` даёт список реально переданных флагов (так уже сделано для `-palette`, `paletteFlagSet`).

## 4. Файлы и каталог (идея 2)

### 4.1 Общий файл `config`

**Предлагаю** добавить в `~/.config/doomcode/` файл **`config`** для общих настроек, а `keys`, `theme`, `fmt` оставить отдельными: это списки, их удобно сбрасывать и переносить по частям. Формат тот же, что у остальных: `имя значение`, `#` — комментарий.

```
# ~/.config/doomcode/config
font          /mnt/font/HelveticaNeue/14a/font
font.fixed    /mnt/font/Menlo-Regular/14a/font
palette       auto            # auto | имя палитры | путь к файлу темы
palette.light doom-light      # для auto
palette.dark  doom-dark
window        1600x1000       # как -W
columns       2               # как -c
autoindent    off             # как -a
focus         click           # click | mouse (как -b)
tabstop       4               # сейчас переменная окружения tabstop
tabexpand     off
```

Переменные окружения `tabstop`, `tabexpand` продолжают работать и стоят между флагом и конфигом (они тоже «аргументы запуска»). Неизвестные имена и ошибки — сообщение в `+Errors`, строка пропускается.

### 4.2 Пример конфига в комплекте

**Предлагаю** каталог **`config/`** в корне репозитория: `config`, `keys`, `theme`, `fmt` и `themes/`, где **все** значения по умолчанию записаны явно и прокомментированы. Это одновременно документация, заготовка и эталон для сброса. Файлы вшиваются в программу (`go:embed`), чтобы команды ниже работали и без репозитория рядом. Тест следит, что примеры совпадают с умолчаниями в коде (иначе пример начнёт врать).

### 4.3 Команды и клавиши

| Команда / клавиша | Действие |
|---|---|
| **`Cmd-,`**, **`Ctrl-B ,`** | `Config`: открыть каталог `~/.config/doomcode` (создать, если нет); из списка файлов Ctrl-O открывает нужный |
| `Config init` | скопировать примеры из комплекта в каталог настроек для тех файлов, которых там ещё нет; существующие не трогать |
| `Config reset <файл>` | заменить файл примером; старый сохранить рядом как `<файл>.bak` |
| `Config reload` | перечитать все файлы (`keys`, `theme`, `fmt`, `config`); то, что требует перезапуска (размер окна), — сообщение в `+Errors` |
| `Config file`, `Config defaults` | путь к каталогу; все значения по умолчанию в синтаксисе `config` |

`Cmd-,` — стандарт macOS для настроек, `Ctrl-B ,` — для Linux и привыкших к префиксу; обе клавиши свободны (проверено 2026-10-08).

## 5. Системная тема и шрифты (идея 3)

### 5.1 `palette auto`

**Предлагаю** по умолчанию `palette auto`: светлая палитра, когда система в светлом оформлении, тёмная — в тёмном, с переключением на ходу.

- **Как узнать оформление.** macOS: `defaults read -g AppleInterfaceStyle` (выводит `Dark` или завершается с ошибкой в светлом режиме). Linux: `gsettings get org.gnome.desktop.interface color-scheme` (`prefer-dark`), иначе светлая.
- **Как заметить смену.** devdraw о смене оформления не сообщает. Варианты:
  1. **Опрос** раз в 3 секунды из горутины редактора. Просто, работает везде, стоит один короткий процесс раз в 3 с. **Предлагаю для первой версии.**
  2. **Патч devdraw** (наша ветка `devdraw/modkeys` plan9port): подписка на `AppleInterfaceThemeChangedNotification` и событие клиенту. Мгновенно, но расширяет протокол devdraw. Позже, если опрос окажется заметным.
- **Что нужно в редакторе.** Сейчас палитру окон можно сменить только перезапуском: каждый frame копирует цвета при создании. Нужна смена палитры на ходу — заново выделить цвета, пройти все окна, колонки и строку тегов, перерисовать. Заодно это даст `Theme reload` для слотов палитры и команду `Theme <имя>` для пробы тем. Это основная работа в коде.

### 5.2 Шрифты

- `font` и `font.fixed` в `config`, порядок §3. Команда `Font` в теге (переключение пропорциональный/моноширинный) берёт значения уже после применения конфига.
- **Предлагаю умолчания на macOS** — системные шрифты через `/mnt/font/…` (проверено 2026-10-08: Menlo 14 рисуется чётко): пропорциональный `HelveticaNeue` или `Avenir-Book`, моноширинный `Menlo-Regular`, 13–14 пунктов. Шрифты семейства SF (SF Pro, SF Mono) `fontsrv` не видит: macOS скрывает системные UI-шрифты из списка; их можно поставить отдельно с сайта Apple, тогда они появятся. Сейчас по умолчанию Lucida из plan9port — мелкая на современных экранах. На Linux — `DejaVu Sans` / `DejaVu Sans Mono` или Lucida, если системных нет. Если шрифт не найден — откат на Lucida plan9port и сообщение.

## 6. Мягкие палитры (идея 6)

**Проблема** (пользователь): резкий контраст между яркими и тёмными цветами.

**Предлагаю** две новые палитры по умолчанию для `palette auto` — **`doom-light`** и **`doom-dark`**; `acme`, `vampira`, `solarized*` остаются для желающих. Правила подбора:

| Что | Правило |
|---|---|
| Фон | не чисто белый и не чисто чёрный: светлая около `#f7f5f0`–`#fafafa`, тёмная около `#1e2127`–`#282c34` |
| Основной текст | контраст с фоном около 10:1 (не 21:1, как чёрный на белом) |
| Комментарии, второстепенное | около 4.5:1 (минимум WCAG AA) |
| Цвета подсветки | одной светлоты и насыщенности, различаются оттенком; каждый не ниже 4.5:1 к фону |
| Выделение, теги | низкий контраст к фону, но заметный; тег отличается от тела оттенком, а не яркостью |
| Диагностика | мягкий фон и подчёркивание приглушённым красным/жёлтым, без «кричащего» красного |

- **Источник цветов** — проверенные палитры с открытыми лицензиями (например One Light/One Dark, Catppuccin Latte/Mocha, Nord), с указанием источника и лицензии в файле темы.
- **Проверка** — тест считает контраст по формуле WCAG для каждой встроенной палитры и падает, если пара выходит за диапазон таблицы; плюс скриншоты обеих палитр для сравнения (сценарий `docs/images/screenshot/shoot.sh` принимает палитру).
- **Темы файлами.** Встроенные палитры переносятся из кода в файлы `config/themes/<имя>` (формат файла `theme`), вшитые в программу; свой файл в `~/.config/doomcode/themes/` с тем же именем перекрывает встроенный. Это мост к идее 5 («больше тем»).

## 7. Открытые вопросы

1. **Один общий файл `config` плюс `keys`/`theme`/`fmt`** (как в §4.1) — или всё в одном файле с разделами?
2. **Опрос раз в 3 секунды** для `palette auto` в первой версии — подходит, или сразу патч devdraw?
3. **Имена новых палитр** `doom-light` / `doom-dark` — подходят?
4. **Шрифты по умолчанию на macOS**: пропорциональный для текста (как в Acme) и моноширинный для кода — или моноширинный везде? Menlo как моноширинный — подходит?
5. **Остаётся ли `acme` (жёлтая) палитрой по умолчанию** для тех, кто запускает без конфига, или по умолчанию сразу `auto`?

## 8. Порядок работ (после ответов)

1. Справка `docs/configuration.md` (готово) и каталог примеров `config/` с тестом «пример = умолчания».
2. Файл `config`, порядок значений §3, шрифты; команды `Config`, `Config init/reset/reload/defaults`, клавиши `Cmd-,` и `Ctrl-B ,`.
3. Смена палитры на ходу; `Theme <имя>`; `Theme reload` для слотов.
4. Палитры `doom-light`/`doom-dark` с тестом контраста; темы файлами.
5. `palette auto` с опросом системы.

Каждый шаг — тесты, запись в `docs/90`, пункт в `docs/test-plan.md`, обновление `docs/configuration.md`.
