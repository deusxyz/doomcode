# Спецификация клавиатуры (черновик 1)

База: Edwood (форк). Схема: CUA + префикс `Ctrl-B` в стиле tmux. Все мышиные действия Acme сохраняются без изменений; клавиатура получает эквиваленты B2, B3 и управления окнами. Дата: 2026-10-05.

## 0. Ограничение, от которого всё зависит: протокол devdraw

Edwood получает клавиатуру через devdraw (plan9port, C) или его Go-версию (9fans.net/go/cmd/devdraw). Оба передают **одну руну на нажатие**, без флагов модификаторов. Проверено по `mac-screen.m` (`doCommandBySelector`, `keycvt`), `x11-screen.c` и `screen.go` (там буквально стоит `// TODO keyboard modifiers`).

Что доходит до редактора:

| Нажатие | Что приходит | Пригодно |
|---|---|---|
| Буква, цифра, знак | сама руна | да |
| Ctrl + буква | управляющий символ 0x01–0x1A (`Ctrl-A`=0x01 … `Ctrl-Z`=0x1A), плюс 0x1B–0x1F для `Ctrl-[ \ ] ^ _` | да, 31 комбинация |
| Ctrl + Space, Ctrl + ` | 0x00, **отбрасывается** devdraw (`if(k>0)`) | нет |
| Cmd + печатный символ (только macOS) | 0xF100 + символ; с Shift буква становится заглавной | да, только macOS |
| Стрелки, Home, End, PgUp, PgDn, Ins, Del, F1–F12 | коды 0xF00D–0xF018, KF\|n | да |
| **Shift / Ctrl / Alt + стрелка** и т.п. | **тот же код, что без модификатора** | **нет** |
| Ctrl + Enter | `\n`, как Enter | нет |
| Alt/Option + буква (macOS) | составной символ (`∫`, `ƒ`) через систему ввода; Option отдельно — `Kalt` (compose) | нет |
| Shift + Tab (macOS) | предположительно 0x19 (= `Ctrl-Y`), требует проверки | проверить |

Следствия для дизайна:

1. **Фаза 1** использует только то, что доходит сегодня: Ctrl-буквы, спецклавиши без модификаторов, префикс `Ctrl-B`, Cmd-буквы на macOS. Выделение с клавиатуры делается через **режим якоря** (как copy-mode в tmux: `Ctrl-B Space` начинает выделение, движение расширяет его), а не через Shift.
2. **Фаза 2** расширяет devdraw: для спецклавиш с модификаторами вводятся новые коды в Private Use Area, и тогда появляются Shift+стрелки, Ctrl+стрелки, Ctrl+Enter, Ctrl+Backspace. Протокол и обе реализации devdraw (C и Go) у нас в руках: plan9port установлен из исходников, Go-версия лежит в `~/projects/9fans/go`. Раздел 7.

Таблицы ниже помечают колонкой «Фаза», что работает сразу, а что ждёт расширения.

## 1. Принципы

1. Клавиатура даёт те же три действия, что мышь: выделить, выполнить (B2), найти/открыть (B3). Новых семантик не вводится.
2. CUA там, где нет конфликта с Acme. Где конфликт есть, решение зафиксировано в разделе 6.
3. Все операции над окнами и колонками — через префикс `Ctrl-B`, как в tmux. Прямых Ctrl-комбинаций на окна нет: Ctrl-символов всего 31, они нужны для редактирования.
4. После клавиатурной смены фокуса указатель мыши переносится в окно фокуса. Это сохраняет работоспособность мышиных действий и правила «ввод идёт под мышь» в режиме без `-b`.
5. Ни одна клавиша не уничтожает текст без записи в undo.
6. Диалогов нет: «найти», «перейти к строке», «выполнить команду» — это тег. `Ctrl-B :` ставит курсор в тег, как `:` в tmux открывает командную строку.
7. Все привязки — в конфигурационном файле, в коде только значения по умолчанию.

## 3. Выделение

| Клавиша | Действие | Фаза |
|---|---|---|
| Ctrl-B Space | **поставить якорь**: дальнейшее движение (← → ↑ ↓ Home End, Ctrl-B g/G) расширяет выделение между якорем и кареткой. Выход из режима — ввод текста, Ctrl-C/X/V, щелчок мышью, Esc (оставляет каретку, снимает выделение) | 1, готово |
| Ctrl-A | выделить всё | 1, готово |
| Ctrl-L | выделить текущую строку целиком; повтор — добавить следующую строку | 1, готово |
| Ctrl-D | выделить слово под курсором (как двойной клик); если есть выделение — найти следующее вхождение (семантика Look, по кругу) | 1, готово |
| Ctrl-B b | выделить текст внутри ближайших объемлющих скобок `()[]{}`; повтор — включить скобки, затем следующий уровень | 1, готово (кавычки не поддержаны) |
| Esc | как в Acme: выделить набранное с последнего действия мыши; при наличии выделения — вырезать | 1 |
| Shift + ← → ↑ ↓ Home End PgUp PgDn | расширить выделение | 2 |
| Ctrl-Shift-← → | выделить слово | 2 |

Якорь хранится в `Text` (`anchorOn`, `anchor`). Каретка — конец выделения, противоположный якорю; движение вычисляется от каретки и вызывает `moveCaret`, который без якоря схлопывает выделение, а с якорем строит `[min(anchor,q), max)`. Известное ограничение: при расширении вниз прокрутка следует за началом выделения, а не за кареткой.

## 5. Команды, поиск, окна

### 5.1 Прямые комбинации

| Клавиша | Действие | Эквивалент мыши | Фаза |
|---|---|---|---|
| **Ctrl-E** | **Execute**: выполнить выделение, а если его нет — слово под курсором (`execute(t, q0, q1, false, nil)`) | B2 | 1 |
| **Ctrl-O** | **Open/Look**: открыть файл, перейти по адресу или найти выделение/слово под курсором (`look3(t, q0, q1, false)`) | B3 | 1 |
| Ctrl-B Enter / Ctrl-B l | то же, что Ctrl-E / Ctrl-O (для привычных к tmux); `o` занят под «следующее окно», как в tmux, `/` — под комментирование | B2 / B3 | 1 |
| Ctrl-Enter / Alt-Enter | то же, что Ctrl-E / Ctrl-O; Cmd-Enter = Execute. У пользователя правый Alt переназначен в Cmd средствами macOS (Modifier Keys), поэтому правый Alt+Enter выполняет, а не открывает — это настройка системы, не редактора | B2 / B3 | 2, готово |
| Ctrl-S / Cmd-S | Put | B2 на `Put` | 1 |
| Ctrl-F | Поиск (Cmd-F занят devdraw, §13): с выделением — найти следующее вхождение; без — в тег дописывается `Look `, вы набираете текст, **Esc** выделяет `Look текст`, **Ctrl-E** выполняет | B3 | 1, готово |
| F3 / Ctrl-B n | найти следующее вхождение выделения или последнего поиска | повторный B3 | 1, готово |
| Ctrl-N / Cmd-N | New | B2 на `New` | 1, готово |

Почему `Ctrl-E` и `Ctrl-O`, а не `Ctrl-Enter`/`Alt-Enter` сразу: Ctrl-Enter в протоколе неотличим от Enter. Мнемоника: Execute, Open. Старое значение `Ctrl-E` (конец строки) переезжает на End.

Механика: `Ctrl-B` (0x02) переводит клавиатурный поток в состояние «ожидание ключа» без таймаута. В отличие от tmux, `Ctrl-B Ctrl-B` **не** вводит литеральный символ: devdraw доставляет автоповтор как обычные нажатия, и удержанный чуть дольше Ctrl-B вставлял бы управляющие символы и сбрасывал префикс; повторный Ctrl-B просто держит префикс взведённым. Индикация: курсор мыши меняет форму (так Acme показывает аккорды), в самом тексте ничего не рисуется. Неизвестная клавиша после префикса игнорируется и сбрасывает состояние.

### 5.3 Фокус

**Фокус по щелчку (по умолчанию).** Ввод идёт в окно, по которому последним щёлкнули или в которое перешли с клавиатуры, а не в окно под мышью. Иначе выделение в одном окне и случайный увод мыши в другое отправляли Ctrl-O туда, куда не нужно (замечание от 2026-10-05). Это существующий режим Edwood `-b`, теперь включённый по умолчанию; `-b=false` возвращает акмовское «ввод под мышью». До первого щелчка ввод идёт под мышь, чтобы редактор не молчал после запуска.

Клавиатурная навигация (`Ctrl-B` + стрелки и т.д.) меняет фокус и переносит указатель мыши в окно фокуса, чтобы мышиные действия и аккорды относились к тому же окну. Прокрутка колесом по-прежнему действует на окно под мышью.

**Переход по адресу переносит фокус.** После `Ctrl-O` (и B3) на `:55` или `/regexp/` в теге фокус ввода уходит в тело окна, куда указатель переносится и в Acme; так же при открытии файла — в новое окно. Выделение остаётся акмовским: `:55` выделяет строку целиком (это семантика адреса, `:/re/` должен подсветить совпадение); `←` ставит каретку в начало строки, `→` — в конец.

**Набор в теге переживает перенос указателя.** Acme заканчивает «набранное» (то, что выделит Esc) при уходе мыши из текста. При фокусе по щелчку или липком клавиатурном фокусе мышь не решает, куда идёт ввод, поэтому и набор не прерывает: иначе `:` после `Ctrl-G` терялось из-за самого переноса указателя в тег, и Esc выделял только номер строки.

## 7. Фаза 2: модификаторы спецклавиш в devdraw (готово, проверено 2026-10-05)

Реализовано патчем C-devdraw из plan9port, ветка `devdraw/modkeys` форка deusxyz/plan9port (коммит `efc9ace7`), бинарник `$PLAN9/bin/devdraw` пересобран (`cd src/cmd/devdraw && 9 mk install`).

- Диапазон рун `0xF200–0xF3FF`: `Kmod | mods<<5 | key`; `Kmod = 0xF200` добавлен в `include/keyboard.h`; `mods` — биты 1 Shift, 2 Ctrl, 4 Alt/Option, 8 Cmd/Super; `key` — 1 ←, 2 →, 3 ↑, 4 ↓, 5 Home, 6 End, 7 PgUp, 8 PgDn, 9 Ins, 10 Del, 11 Backspace, 12 Tab, 13 Enter, 14 Esc. Логика в `src/cmd/devdraw/modkeys.h`, общая для `mac-screen.m` и `x11-screen.c`; Shift+Tab (NSBackTabCharacter / XK_ISO_Left_Tab) — Tab с Shift. На X11 заодно перестал портиться Ctrl+стрелка (маска `& 0x9f`).
- Включается переменной `DEVDRAW_MODKEYS=1`; Edwood ставит её сам перед запуском devdraw (`acme.go`). Без переменной поведение прежнее, plan9port acme и 9term ничего не замечают.
- Edwood (`keysmod.go`): имена `S-Left`, `C-S-Right`, `M-Enter`, `Cmd-Up` в `keys` и `Keys`; привязки по умолчанию: Shift+движение расширяет выделение через якорь, Ctrl+←/→ по словам, Ctrl+Shift+←/→ выделяет слово, Ctrl+Home/End начало/конец файла, Ctrl+↑/↓ прокрутка на строку, Ctrl+Enter и Cmd+Enter = Execute, Alt+Enter = Look, Ctrl+Backspace/Ctrl+Del удаляют слово, Shift+Tab = outdent, Cmd+←/→ начало/конец строки, Cmd+↑/↓ начало/конец файла, Shift+PgUp/PgDn выделяют страницу, Option+←/→ по словам, Option+Shift+←/→ выделяют слово, Option+↑/↓ прокрутка на строку. Непривязанная модифицированная клавиша — no-op, в текст не попадает.
- **macOS перехватывает Ctrl+←/→/↑/↓** (Mission Control, рабочие столы) ещё до devdraw; это решено не чинить — вместо них Option+стрелки, как принято на Mac. Ctrl+стрелки заработают, если отключить системные сочетания в System Settings → Keyboard → Keyboard Shortcuts → Mission Control.
- Проверено пользователем 2026-10-05: Shift+стрелки, Ctrl+Enter, Shift+Tab и остальное работают; Ctrl+стрелки не доходят (система, см. выше); Shift+PgUp/PgDn печатали руну — исправлено (no-op для непривязанных, привязка `select-page-*`).

## 8. Конфигурация

Файл `$EDWOOD_KEYS`, иначе `$XDG_CONFIG_HOME/edwood/keys`, иначе `$HOME/.config/edwood/keys`. По строке на привязку, `#` — комментарий, `-` вместо действия снимает привязку. Файл накладывается на привязки по умолчанию, поэтому в нём только изменения:

```
# клавиша        действие
C-q              put
F2               execute
C-k              -                 # вернуть ^K под ввод текста
Cmd-r            redo
```

Имена клавиш: `C-x` Ctrl, `Cmd-x` Command (с заглавной — Cmd-Shift), спецклавиши `Left Right Up Down Home End PgUp PgDn Ins Del Backspace Tab Enter Esc Space F1..F12`, одиночный символ — сам символ, `0xF800` — сырой код. Имена действий — из таблицы `actionTable` в `keys.go`; `Keys actions` печатает их с описаниями. Префиксные привязки (`prefix x`) и `S-`/`M-` появятся вместе с префиксом и фазой 2.

Команда `Keys` (встроенная, вывод в `+Errors`): без аргумента — текущие привязки и путь к файлу; `Keys reload` — перечитать файл поверх умолчаний; `Keys actions` — список действий; `Keys file` — путь. Ошибки в файле не отменяют остальные строки: плохая строка пропускается и печатается с номером, при старте — в stderr, при `Keys reload` — в `+Errors`.

## 9. Где это ложится в код Edwood

- `text.go` `Type()` (строки ~840–1050): сегодня `switch r`. Заменяется на таблицу `map[rune]Action` и состояние якоря; движение по строкам требует «целевой колонки» (sticky column) и использует `frame.Ptofchar`/`Charofpt`.
- `acme.go` `keyboardthread` (строка 401): сюда ставится автомат префикса, потому что действия над окнами выполняются на уровне `Row`, а не `Text`. `row.Type` (row.go:267) выбирает цель: `barttext` при `-b`, иначе окно под мышью. Заменяется на `focus`.
- `exec.go` `execute(t, q0, q1, external, argt)` и `look.go` `look3(t, q0, q1, external)` вызываются напрямую для Ctrl-E / Ctrl-O. Если `q0==q1`, они сами расширяют до слова, как при клике.
- Обход окон: `row.col[]`, `col.w[]`; изменение размеров — существующие функции layout box в `col.go`/`wind.go`.
- Перенос мыши: `display.MoveTo`, уже используется Acme после B3.

## 12. Решения от 2026-10-05

1. `Ctrl-E` / `Ctrl-O` — клавиатурные B2 / B3; дубли `Ctrl-B Enter` / `Ctrl-B o` остаются.
2. Перенос мыши к окну фокуса — **всегда**, независимо от `-b`.
3. Префикс `Ctrl-B` — **без таймаута**, как в tmux.

## 13. macOS: слой Cmd

На macOS привычный модификатор для команд редактора — Cmd, и devdraw уже доставляет `Cmd+символ` отдельным кодом (`0xF100+символ`). Поэтому:

- **Все CUA-команды редактирования и команды Acme получают Cmd-вариант на macOS**, Ctrl-вариант при этом тоже работает (одинаковая мышечная память на Linux и Mac, где удобнее). Пары: Cmd-C/X/V/Z/Shift-Z, Cmd-A, Cmd-S (Put), Cmd-E (Execute), Cmd-O (Look), Cmd-N (New), Cmd-/ (комментирование), Cmd-D, Cmd-L, Cmd-K, Cmd-G.
- **Префикс остаётся `Ctrl-B` на всех ОС**: он из tmux, и там он одинаков везде. Ctrl-W, Ctrl-U, Ctrl-K как Unix-привычки тоже остаются на Ctrl.
- Что занято и в привязки не идёт: `Cmd-Q` (выход), `Cmd-H` (скрыть), `Cmd-M` (свернуть), `Cmd-Tab`, `Cmd-Space` — забирает система; в Go-devdraw `Cmd-R` переключает DPI (при форке можно вынести на другую клавишу). В C-devdraw из plan9port дополнительно занят `Cmd-F` (Toggle Full Screen, пункт меню); решение пользователя — оставить его devdraw, поэтому поиск только на Ctrl-F, привязки `Cmd-f` нет.
- `Cmd+стрелки` через devdraw не отличимы от стрелок (как и Shift/Ctrl), это тоже фаза 2.

## 15. Пересмотр решения о devdraw (2026-10-05)

Сравнение на практике показало, что Go-devdraw из 9fans.net/go непригоден как рантайм без большой доработки: заметно медленная отрисовка (полная перезаливка буфера через shiny), не реализованы курсоры (`rpc_setcursor` — заглушка, а у драйвера shiny нет API курсоров), не обрабатывается колесо мыши, Backspace приходит как 0x7F (Delete), а Forward Delete не приходит вовсе. Всё это в C-devdraw из plan9port давно работает, включая автоповтор и Cmd-клавиши.

Решение: **база для фазы 2 — C-devdraw из plan9port.** Расширение протокола (§7, коды `0xF200`, включение через `DEVDRAW_MODKEYS=1`) делается патчем в `src/cmd/devdraw/mac-screen.m` (`doCommandBySelector`: читать `modifierFlags` перед `keycvt`) и `x11-screen.c`, в форке github.com/9fans/plan9port. Объём патча — десятки строк, оба файла уже прочитаны. Форк 9fans-go сохраняем ради PR в upstream. Пункт 5 решений от 2026-10-05 отменён.
