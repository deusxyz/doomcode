# Спецификация клавиатуры (черновик 1)

База: Edwood (форк). Схема: CUA + префикс `Ctrl-B` в стиле tmux. Все мышиные действия Acme сохраняются без изменений; клавиатура получает эквиваленты B2, B3 и управления окнами. Дата: 2026-10-05.

## 0. Ограничение, от которого всё зависит: протокол devdraw

Edwood получает клавиатуру через devdraw (plan9port, C) или его Go-версию (9fans.net/go/cmd/devdraw). Оба передают **одну руну на нажатие**, без флагов модификаторов. Проверено по `mac-screen.m` (`doCommandBySelector`, `keycvt`), `x11-screen.c` и `screen.go` (там буквально стоит `// TODO keyboard modifiers`).

Что доходит до редактора:

| Нажатие | Что приходит | Пригодно |
|---|---|---|
| Буква, цифра, знак | сама руна | да |
| Ctrl + буква | управляющий символ 0x01–0x1A (`Ctrl-A`=0x01 … `Ctrl-Z`=0x1A), плюс 0x1B–0x1F для `Ctrl-[ \ ] ^ _` | да, 31 комбинация |
| Ctrl + Space, Ctrl + ` | 0x00, **отбрасывается** devdraw (`if(k>0)`) | нет |
| Cmd + печатный символ (только macOS) | 0xF100 + символ; с Shift буква становится заглавной | да, только macOS |
| Стрелки, Home, End, PgUp, PgDn, Ins, Del, F1–F12 | коды 0xF00D–0xF018, KF\|n | да |
| **Shift / Ctrl / Alt + стрелка** и т.п. | **тот же код, что без модификатора** | **нет** |
| Ctrl + Enter | `\n`, как Enter | нет |
| Alt/Option + буква (macOS) | составной символ (`∫`, `ƒ`) через систему ввода; Option отдельно — `Kalt` (compose) | нет |
| Shift + Tab (macOS) | предположительно 0x19 (= `Ctrl-Y`), требует проверки | проверить |

Следствия для дизайна:

1. **Фаза 1** использует только то, что доходит сегодня: Ctrl-буквы, спецклавиши без модификаторов, префикс `Ctrl-B`, Cmd-буквы на macOS. Выделение с клавиатуры делается через **режим якоря** (как copy-mode в tmux: `Ctrl-B Space` начинает выделение, движение расширяет его), а не через Shift.
2. **Фаза 2** расширяет devdraw: для спецклавиш с модификаторами вводятся новые коды в Private Use Area, и тогда появляются Shift+стрелки, Ctrl+стрелки, Ctrl+Enter, Ctrl+Backspace. Протокол и обе реализации devdraw (C и Go) у нас в руках: plan9port установлен из исходников, Go-версия лежит в `~/projects/9fans/go`. Раздел 7.

Таблицы ниже помечают колонкой «Фаза», что работает сразу, а что ждёт расширения.

## 1. Принципы

1. Клавиатура даёт те же три действия, что мышь: выделить, выполнить (B2), найти/открыть (B3). Новых семантик не вводится.
2. CUA там, где нет конфликта с Acme. Где конфликт есть, решение зафиксировано в разделе 6.
3. Все операции над окнами и колонками — через префикс `Ctrl-B`, как в tmux. Прямых Ctrl-комбинаций на окна нет: Ctrl-символов всего 31, они нужны для редактирования.
4. После клавиатурной смены фокуса указатель мыши переносится в окно фокуса. Это сохраняет работоспособность мышиных действий и правила «ввод идёт под мышь» в режиме без `-b`.
5. Ни одна клавиша не уничтожает текст без записи в undo.
6. Диалогов нет: «найти», «перейти к строке», «выполнить команду» — это тег. `Ctrl-B :` ставит курсор в тег, как `:` в tmux открывает командную строку.
7. Все привязки — в конфигурационном файле, в коде только значения по умолчанию.

## 3. Выделение

| Клавиша | Действие | Фаза |
|---|---|---|
| Ctrl-B Space | **поставить якорь**: дальнейшее движение (← → ↑ ↓ Home End PgUp PgDn, Ctrl-B g/G) расширяет выделение от якоря. Выход из режима — любое редактирование, Ctrl-C/X, Esc (схлопнуть к курсору) | 1 |
| Ctrl-A | выделить всё | 1 |
| Ctrl-L | выделить текущую строку целиком; повтор — добавить следующую строку | 1 |
| Ctrl-D | выделить слово под курсором (как двойной клик); если слово уже выделено — найти и выделить следующее вхождение (семантика B3/Look) | 1 |
| Ctrl-B b | выделить блок в скобках/кавычках вокруг курсора (как двойной клик у скобки в Acme) | 1 |

Якорь хранится в `Text` (новое поле `anchor`, -1 если нет). Пока якорь активен, `Show(q0,q0)` в обработчиках движения заменяется на `SetSelect(min(anchor,q), max(anchor,q))`.

## 5. Команды, поиск, окна

### 5.1 Прямые комбинации

| Клавиша | Действие | Эквивалент мыши | Фаза |
|---|---|---|---|
| **Ctrl-E** | **Execute**: выполнить выделение, а если его нет — слово под курсором (`execute(t, q0, q1, false, nil)`) | B2 | 1 |
| **Ctrl-O** | **Open/Look**: открыть файл, перейти по адресу или найти выделение/слово под курсором (`look3(t, q0, q1, false)`) | B3 | 1 |
| Ctrl-B Enter / Ctrl-B / | то же, что Ctrl-E / Ctrl-O (для привычных к tmux); `o` занят под «следующее окно», как в tmux | B2 / B3 | 1 |
| Ctrl-Enter / Alt-Enter | то же, что Ctrl-E / Ctrl-O | B2 / B3 | 2 |
| Ctrl-S / Cmd-S | Put | B2 на `Put` | 1 |
| Ctrl-F / Cmd-F | Поиск: курсор в тег после `Look `, набрать текст, Ctrl-E; если есть выделение — сразу искать его дальше | B3 | 1 |
| F3 / Ctrl-B n | найти следующее вхождение последнего поиска | повторный B3 | 1 |
| Ctrl-N / Cmd-N | New | B2 на `New` | 1 |

Почему `Ctrl-E` и `Ctrl-O`, а не `Ctrl-Enter`/`Alt-Enter` сразу: Ctrl-Enter в протоколе неотличим от Enter. Мнемоника: Execute, Open. Старое значение `Ctrl-E` (конец строки) переезжает на End.

### 5.2 Префикс Ctrl-B (управление окнами, как в tmux)

| После Ctrl-B | Действие | Аналог tmux | Аналог Acme |
|---|---|---|---|
| ← → | фокус в соседнюю колонку, в окно, ближайшее по вертикали | prefix ← → | клик мышью |
| ↑ ↓ | фокус в окно выше/ниже в колонке | prefix ↑ ↓ | клик |
| o | следующее окно (по колонкам, сверху вниз, по кругу) | prefix o | — |
| ; | предыдущее активное окно | prefix ; | — |
| 0–9 | n-е окно текущей колонки (0 = тег колонки) | prefix 0–9 | — |
| q | на 1,5 с показать номера окон в их layout box | prefix q | — |
| w | открыть окно `+windows` со списком всех окон (`id путь`), B3/Ctrl-O переходит | prefix w | окно-список, как `index` |
| : | курсор в конец тега текущего окна (командная строка) | prefix : | клик в тег |
| t | переключить фокус тег ⇄ тело | — | — |
| c | New (новое окно в текущей колонке) | prefix c | `New` |
| % | Newcol | prefix % | `Newcol` |
| x | Del (с проверкой dirty, второй раз — Delete) | prefix x | `Del` |

| + / − | увеличить / уменьшить окно на несколько строк (− пока не реализован: в Acme нет «уменьшить») | prefix Ctrl-↑↓ | B1 в layout box |
| { } | переместить окно вверх/вниз в колонке | prefix { } | перетаскивание |
| [ ] | переместить окно в соседнюю колонку | — | перетаскивание |
| s | Sort окон в колонке | — | `Sort` |
| S | Putall | — | `Putall` |
| g / G | начало / конец файла | — | Home / End |
| / | Look (B3) | — | B3 |
| Space | якорь выделения (раздел 3) | copy-mode Space | — |
| b | выделить блок (раздел 3) | — | двойной клик |
| Tab | сдвиг строк влево (раздел 4) | — | — |
| Esc | отменить префикс | — | — |

Механика: `Ctrl-B` (0x02) переводит клавиатурный поток в состояние «ожидание ключа» без таймаута. В отличие от tmux, `Ctrl-B Ctrl-B` **не** вводит литеральный символ: devdraw доставляет автоповтор как обычные нажатия, и удержанный чуть дольше Ctrl-B вставлял бы управляющие символы и сбрасывал префикс; повторный Ctrl-B просто держит префикс взведённым. Индикация: курсор мыши меняет форму (так Acme показывает аккорды), в самом тексте ничего не рисуется. Неизвестная клавиша после префикса игнорируется и сбрасывает состояние.

### 5.3 Фокус

Сейчас Edwood без `-b` печатает в окно под мышью, с `-b` — в последнее кликнутое (`global.barttext`). Для клавиатурной навигации вводится **явный фокус** всегда: `focus = последнее окно, где был клик или нажатие`. Префиксные команды меняют `focus`, затем переносят мышь в центр первой видимой строки тела (`display.MoveTo`), чтобы режим без `-b` не расходился с фокусом. Опция `warp=off` отключает перенос для тех, кто живёт в `-b`.

## 7. Фаза 2: модификаторы спецклавиш в devdraw

Предложение расширения протокола (совместимое: включается явно):

- Новый диапазон рун `0xF200–0xF2FF`: `0xF200 | mods<<5 | key`, где `mods` — биты 1 Shift, 2 Ctrl, 4 Alt/Option; `key` — 1 ←, 2 →, 3 ↑, 4 ↓, 5 Home, 6 End, 7 PgUp, 8 PgDn, 9 Ins, 10 Del, 11 Backspace, 12 Tab, 13 Enter, 14 Esc. Не пересекается с `KF` (0xF000–0xF0FF) и `Kcmd` (0xF100–0xF17E).
- Код посылается только если есть хотя бы один модификатор; без модификаторов — как сейчас.
- Включается переменной окружения `DEVDRAW_MODKEYS=1`, которую Edwood выставляет при запуске devdraw. Непропатченные клиенты (plan9port acme, 9term) ничего не замечают, потому что без переменной поведение прежнее. Это важно: иначе стоковый acme вставлял бы неизвестные руны как текст.
- Изменения: `mac-screen.m` (`doCommandBySelector`: читать `modifierFlags` перед `keycvt`), `x11-screen.c` (`state & ShiftMask/ControlMask/Mod1Mask` в обработке XKeyEvent), `9fans.net/go/cmd/devdraw/screen.go` (`e.Modifiers` уже доступен в `key.Event`), константы в `9fans.net/go/draw/keyboard.go` и в `edwood/draw`.
- Альтернатива без патча plan9port: Edwood поставляет свою сборку Go-devdraw (чистый Go, shiny) и запускает её вместо `$PLAN9/bin/devdraw`. Качество Go-devdraw надо проверить отдельно: в коде есть TODO по мыши и размеру окна.

## 8. Конфигурация

Файл `$EDWOOD_KEYS`, иначе `$XDG_CONFIG_HOME/edwood/keys`, иначе `$HOME/.config/edwood/keys`. По строке на привязку, `#` — комментарий, `-` вместо действия снимает привязку. Файл накладывается на привязки по умолчанию, поэтому в нём только изменения:

```
# клавиша        действие
C-q              put
F2               execute
C-k              -                 # вернуть ^K под ввод текста
Cmd-r            redo
```

Имена клавиш: `C-x` Ctrl, `Cmd-x` Command (с заглавной — Cmd-Shift), спецклавиши `Left Right Up Down Home End PgUp PgDn Ins Del Backspace Tab Enter Esc Space F1..F12`, одиночный символ — сам символ, `0xF800` — сырой код. Имена действий — из таблицы `actionTable` в `keys.go`; `Keys actions` печатает их с описаниями. Префиксные привязки (`prefix x`) и `S-`/`M-` появятся вместе с префиксом и фазой 2.

Команда `Keys` (встроенная, вывод в `+Errors`): без аргумента — текущие привязки и путь к файлу; `Keys reload` — перечитать файл поверх умолчаний; `Keys actions` — список действий; `Keys file` — путь. Ошибки в файле не отменяют остальные строки: плохая строка пропускается и печатается с номером, при старте — в stderr, при `Keys reload` — в `+Errors`.

## 9. Где это ложится в код Edwood

- `text.go` `Type()` (строки ~840–1050): сегодня `switch r`. Заменяется на таблицу `map[rune]Action` и состояние якоря; движение по строкам требует «целевой колонки» (sticky column) и использует `frame.Ptofchar`/`Charofpt`.
- `acme.go` `keyboardthread` (строка 401): сюда ставится автомат префикса, потому что действия над окнами выполняются на уровне `Row`, а не `Text`. `row.Type` (row.go:267) выбирает цель: `barttext` при `-b`, иначе окно под мышью. Заменяется на `focus`.
- `exec.go` `execute(t, q0, q1, external, argt)` и `look.go` `look3(t, q0, q1, external)` вызываются напрямую для Ctrl-E / Ctrl-O. Если `q0==q1`, они сами расширяют до слова, как при клике.
- Обход окон: `row.col[]`, `col.w[]`; изменение размеров — существующие функции layout box в `col.go`/`wind.go`.
- Перенос мыши: `display.MoveTo`, уже используется Acme после B3.

## 10. Критерии приёмки фазы 1

1. Открыть файл, набрать текст, выделить якорем, скопировать, вставить, отменить, повторить — без мыши.
2. Набрать в теге `go build`, выполнить `Ctrl-E`, перейти по `file.go:12:` из `+Errors` через `Ctrl-O` — без мыши.
3. Создать колонку, два окна, переключаться между ними `Ctrl-B` стрелками, закрыть окно `Ctrl-B x` — без мыши; указатель мыши каждый раз в окне фокуса.
4. Все мышиные действия и аккорды работают как в Acme; `win`, `acme-lsp`, `acmego` работают без изменений.
5. Привязка из конфига перекрывает значение по умолчанию.

## 12. Решения от 2026-10-05

1. `Ctrl-E` / `Ctrl-O` — клавиатурные B2 / B3; дубли `Ctrl-B Enter` / `Ctrl-B o` остаются.
2. Перенос мыши к окну фокуса — **всегда**, независимо от `-b`.
3. Префикс `Ctrl-B` — **без таймаута**, как в tmux.
4. `Ctrl-D` — «выделить слово; повтор ищет следующее вхождение».
5. Фаза 2 — поставлять **Go-devdraw** (форк `9fans.net/go/cmd/devdraw`) вместе с Edwood, plan9port не патчить.

## 13. macOS: слой Cmd

На macOS привычный модификатор для команд редактора — Cmd, и devdraw уже доставляет `Cmd+символ` отдельным кодом (`0xF100+символ`). Поэтому:

- **Все CUA-команды редактирования и команды Acme получают Cmd-вариант на macOS**, Ctrl-вариант при этом тоже работает (одинаковая мышечная память на Linux и Mac, где удобнее). Пары: Cmd-C/X/V/Z/Shift-Z, Cmd-A, Cmd-S (Put), Cmd-E (Execute), Cmd-O (Look), Cmd-N (New), Cmd-F (Look/поиск), Cmd-D, Cmd-L, Cmd-K, Cmd-G.
- **Префикс остаётся `Ctrl-B` на всех ОС**: он из tmux, и там он одинаков везде. Ctrl-W, Ctrl-U, Ctrl-K как Unix-привычки тоже остаются на Ctrl.
- Что занято и в привязки не идёт: `Cmd-Q` (выход), `Cmd-H` (скрыть), `Cmd-M` (свернуть), `Cmd-Tab`, `Cmd-Space` — забирает система; в Go-devdraw `Cmd-R` переключает DPI (при форке можно вынести на другую клавишу). В C-devdraw из plan9port дополнительно заняты `Cmd-F` (полный экран) — ещё один довод за Go-devdraw.
- `Cmd+стрелки` через devdraw не отличимы от стрелок (как и Shift/Ctrl), это тоже фаза 2.
