# Настройка doomcode

Справка для пользователя: где лежат настройки, что в них писать и откуда редактор берёт значения, если вы ничего не настраивали. Описано текущее состояние (2026-10-08). Как настройка будет устроена дальше — в `docs/09-config-spec.md`.

## Коротко

- Настройки лежат в каталоге **`~/.config/doomcode/`** (или `$XDG_CONFIG_HOME/doomcode/`, если эта переменная задана).
- После установки каталог **пуст**: файлы создаёте вы, когда хотите что-то поменять. Всё, чего нет в файлах, берётся из **значений по умолчанию, записанных в коде** редактора.
- В файлах пишутся **только изменения** относительно умолчаний, а не полный список.
- Чтобы увидеть текущие значения, наберите в любом теге команду (`Keys`, `Theme`, `Fmt rules`) и выполните её средней кнопкой мыши или **Ctrl-E**. Вывод придёт в окно `+Errors`, его можно скопировать в файл как заготовку.

## Файлы настроек

| Файл | Что задаёт | Перечитать без перезапуска | Переменная, указывающая на другой файл |
|---|---|---|---|
| `~/.config/doomcode/keys` | привязки клавиш | `Keys reload` | `DOOMCODE_KEYS` |
| `~/.config/doomcode/theme` | палитра и цвета подсветки | `Theme reload` (цвета подсветки; цвета окон — после перезапуска) | `DOOMCODE_THEME` |
| `~/.config/doomcode/fmt` | форматирование при сохранении | `Fmt reload` | `DOOMCODE_FMT` |

Во всех файлах пустые строки пропускаются, `#` начинает комментарий до конца строки (в `theme` — если за `#` не следует цвет). Строки с ошибками пропускаются, сообщение о них приходит в `+Errors`, остальные строки применяются.

### `keys` — клавиши

```
# клавиша действие
C-s        put
F5         run go test ./...      # выполнить команду, как средней кнопкой
F6         tag Edit s/x/y/        # дописать текст в тег, чтобы дополнить и выполнить
prefix d   run L def              # после префикса Ctrl-B
C-k        -                      # снять привязку: клавиша снова печатает символ
```

Имена клавиш: `C-x` (Ctrl), `Cmd-x`, `M-x` (Alt/Option), `S-` (Shift) для спецклавиш, сочетания `C-S-Left`; спецклавиши `Left Right Up Down Home End PgUp PgDn Ins Del Backspace Tab Enter Esc Space F1…F12`; `C-/` — Ctrl+/. Команды: `Keys` — все действующие привязки; `Keys actions` — все действия, которые можно назначить; `Keys file` — путь к файлу. Полное описание клавиш — `docs/03-keyboard-spec.md`.

### `theme` — цвета

```
palette doom-dark                  # базовая палитра (если не задана флагом -palette)
style keyword fg=#5f87af           # цвет стиля подсветки: fg=, bg=, line=, underline/nounderline
style comment fg=#7f7f7f
style variable -                   # убрать стиль: рисовать как обычный текст
text.back #fdf6e3                  # цвет окна (слот палитры), применяется после перезапуска
tag.back #eee8d5
```

Цвета: `#rgb`, `#rrggbb`, `#rrggbbaa`. Слоты палитры: `tag.*` и `text.*` (`back high bord text htext tick`), `ui.modbutton ui.colbutton ui.but2 ui.but3`; после цвета можно указать `mix #ffffff` — смесь 50/50. Имена стилей подсветки: `comment keyword string number type function constant preproc heading emphasis link variable operator punctuation error warning info hint match diff.add diff.del diff.change`; имя с точкой (`error.syntax`) без своего цвета берёт цвет имени до точки. Команды: `Theme` — текущие стили в синтаксисе файла; `Theme slots` — список слотов; `Theme file` — путь.

### `fmt` — форматирование при сохранении

```
.go   gofmt -s                        # суффикс или точное имя файла, затем команда
.ts   prettier --stdin-filepath %f    # %f — путь к файлу
Makefile -                            # снять правило
put off                               # не форматировать при Put; команда Fmt работает
```

Команды: `Fmt` — отформатировать окно сейчас; `Fmt rules` — правила; `Fmt file` — путь. Подробно — `docs/07-format-spec.md`.

## Что задано в коде

Если файла нет или в нём нет нужной строки, действует значение из кода:

- **Клавиши** — таблицы в `editor/keys.go` (`defaultBindings`), `editor/keysmod.go` (клавиши с модификаторами) и `editor/prefix.go` (после Ctrl-B).
- **Палитры** — шесть встроенных: `doom-light` (светлая, мягкая; **по умолчанию**) и `doom-dark` (тёмная, по мотивам doom-one) в `editor/theme/doom.go`; `acme` (жёлтая, как в оригинальном Acme), `vampira` (тёмная), `solarizedlight`, `solarizeddark` в `editor/theme/palette.go`. Отдельных файлов тем пока нет. Как подобраны цвета — `docs/10-theme-style-guide.md`.
- **Цвета подсветки** для каждой палитры — в `editor/theme/styles.go`.
- **Форматирование** — одно правило: `.go gofmt`, в `editor/fmtfile.go`.

## Флаги запуска

Флаги задаются в командной строке редактора; `run.sh` передаёт свои аргументы дальше, поэтому `./run.sh -palette vampira файлы` работает.

| Флаг | Что задаёт | По умолчанию |
|---|---|---|
| `-f шрифт` | пропорциональный шрифт | Lucida Sans из plan9port (`run.sh` передаёт `$PLAN9/font/lucsans/euro.8.font`) |
| `-F шрифт` | моноширинный шрифт | Lucida Typewriter (`$PLAN9/font/lucm/unicode.9.font`) |
| `-palette имя` | палитра: `doom-light`, `doom-dark`, `acme`, `vampira`, `solarizedlight`, `solarizeddark` | `doom-light`; перекрывает строку `palette` в файле `theme` |
| `-W 1600x1000@X,Y` | размер и положение окна | `1024x768` |
| `-c N` | число колонок при запуске | 2 |
| `-a` | автоотступ во всех окнах | выключен |
| `-b=false` | фокус под мышью, как в Acme | фокус по щелчку |
| `-r` | поменять местами кнопки прокрутки | нет |
| `-l файл` | восстановить окна из дампа | — |
| `-m путь` | точка монтирования 9P | — |

Шрифты сейчас задаются **только флагами** (в файлах настроек их нет). Шрифт plan9port — путь к файлу `.font`; шрифты системы macOS доступны как `/mnt/font/<Имя>/<размер>a/font`, например `/mnt/font/Menlo-Regular/14a/font`. Список доступных системных шрифтов: `fontsrv -p .` (из plan9port); шрифты семейства SF macOS в нём не видны. Команда `Font` в теге окна переключает его между пропорциональным и моноширинным шрифтом.

## Переменные окружения

| Переменная | Что задаёт |
|---|---|
| `DOOMCODE_KEYS`, `DOOMCODE_THEME`, `DOOMCODE_FMT` | путь к файлу настроек вместо `~/.config/doomcode/…` |
| `XDG_CONFIG_HOME` | каталог настроек: `$XDG_CONFIG_HOME/doomcode` |
| `tabstop` | ширина табуляции (в символах `0`) |
| `tabexpand` | заменять Tab пробелами |
| `acmeshell` | оболочка для команд (по умолчанию `rc` из plan9port) |
| `mousescrollsize` | шаг прокрутки колесом |
| `NAMESPACE` | каталог сервиса 9P; `run.sh` ставит `/tmp/ns.doomcode`, чтобы не мешать plan9port acme. Путь должен быть коротким: в нём создаётся Unix-сокет, а длина его имени ограничена (около 100 символов) |

## Другие файлы

- **`~/doomcode.dump`** — раскладка окон, которую пишет команда `Dump` и читает `Load` (или флаг `-l`).
- **`run.sh`** в корне репозитория — запуск с нужным окружением: путь к devdraw, `NAMESPACE`, шрифты, `~/go/bin` в `PATH` (там `L` из acme-lsp). Свои флаги удобно дописывать в вызов `run.sh`.

## Как начать настраивать

1. Создайте каталог: `mkdir -p ~/.config/doomcode`.
2. Выполните в теге `Keys`, `Theme` или `Fmt rules`, скопируйте из `+Errors` нужные строки в файл и поменяйте.
3. Выполните `Keys reload`, `Theme reload` или `Fmt reload` — изменения применятся сразу (цвета окон — после перезапуска).
4. Чтобы вернуть умолчания, удалите строку или весь файл и снова выполните `… reload`.
