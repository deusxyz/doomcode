# Настройка doomcode

Справка для пользователя: где лежат настройки, что в них писать и откуда редактор берёт значения, если вы ничего не настраивали. Описано текущее состояние (2026-10-09). Что ещё будет — в `docs/09-config-spec.md`.

## Коротко

- Настройки лежат в каталоге **`~/.config/doomcode/`** (или `$XDG_CONFIG_HOME/doomcode/`, если эта переменная задана).
- **Открыть его:** клавиша **Cmd-,** (macOS) или **Ctrl-B ,**, либо команда `Config` в любом теге (выполнить средней кнопкой мыши или **Ctrl-E**). Каталог создаётся, если его нет; Ctrl-O на имени файла открывает файл.
- После установки каталог **пуст**: действуют **значения по умолчанию, записанные в коде**. Команда **`Config init`** копирует туда примеры всех файлов, где каждое значение по умолчанию записано явно и прокомментировано, — это и справка, и заготовка.
- Значение берётся в таком порядке: **флаг запуска → файл настроек → значение по умолчанию**. Флаг всегда побеждает, поэтому настройки можно временно «перегрузить» при запуске.

## Файлы настроек

| Файл | Что задаёт | Применить без перезапуска | Переменная, указывающая на другой файл |
|---|---|---|---|
| `config` | общие настройки: палитра, шрифты, окно, отступы | `Config reload` (палитра, шрифты, окно, колонки — после перезапуска) | `DOOMCODE_CONFIG` |
| `keys` | привязки клавиш | `Keys reload` | `DOOMCODE_KEYS` |
| `theme` | цвета подсветки и окон поверх палитры | `Theme reload` (цвета подсветки; цвета окон — после перезапуска) | `DOOMCODE_THEME` |
| `fmt` | форматирование при сохранении | `Fmt reload` | `DOOMCODE_FMT` |

`Config reload` перечитывает все четыре файла сразу. Во всех файлах пустые строки пропускаются, `#` начинает комментарий до конца строки (в `theme` — если за `#` не следует цвет). Строки с ошибками пропускаются, сообщение о них приходит в `+Errors`, остальные строки применяются.

Примеры в репозитории — каталог [`config/`](../config/); они же вшиты в программу.

| Команда | Действие |
|---|---|
| `Config` (Cmd-, / Ctrl-B ,) | открыть каталог настроек |
| `Config init` | скопировать примеры туда, где файлов ещё нет; существующие не трогаются |
| `Config reset ИМЯ` | заменить файл `ИМЯ` (`config`, `keys`, `theme`, `fmt`) примером; старый сохраняется как `ИМЯ.bak` |
| `Config reload` | перечитать все файлы |
| `Config defaults` | все общие настройки со значениями по умолчанию |
| `Config file` | путь к каталогу |

### `config` — общие настройки

```
palette      doom-dark                            # палитра
font         /mnt/font/Avenir-Book/14a/font       # пропорциональный шрифт
font.fixed   /mnt/font/Menlo-Regular/13a/font     # моноширинный шрифт
window       1600x1000                            # размер окна, можно @X,Y
columns      2                                    # колонок при запуске
autoindent   on                                   # автоотступ
focus        click                                # click — ввод в последнее окно, где щёлкнули; mouse — под мышью
tabstop      4                                    # ширина табуляции
tabexpand    off                                  # on — Tab вставляет пробелы
```

| Настройка | По умолчанию | Перекрывает флаг / переменная |
|---|---|---|
| `palette` | `doom-light` | `-palette` |
| `font`, `font.fixed` | шрифты палитры на macOS, иначе Lucida из plan9port | `-f`, `-F` |
| `window` | `1024x768` | `-W` |
| `columns` | `2` | `-c` |
| `autoindent` | `off` | `-a` |
| `focus` | `click` | `-b` (`-b=false` — под мышью) |
| `tabstop` | `4` | `$tabstop` |
| `tabexpand` | `off` | `$tabexpand` |

**Шрифты.** Каждая палитра doomcode предлагает свои шрифты, и на macOS они берутся, если ни флаг, ни `config` не задали шрифт: `doom-light` — Avenir 14 и Menlo 13, `doom-dark` — Helvetica Neue 14 и Menlo 13. У остальных палитр и на других системах — Lucida из plan9port. Системные шрифты macOS пишутся как `/mnt/font/<Имя>/<размер>a/font`; список — `fontsrv -p .` (из plan9port), шрифты семейства SF в нём не видны. Шрифт plan9port — путь к файлу `.font`. Если шрифт не открывается, редактор запускается с Lucida и пишет об этом в лог. Команда `Font` в теге окна переключает его между пропорциональным и моноширинным шрифтом.

### `keys` — клавиши

```
# клавиша действие
C-s        put
F5         run go test ./...      # выполнить команду, как средней кнопкой
F6         tag Edit s/x/y/        # дописать текст в тег, чтобы дополнить и выполнить
prefix d   run L def              # после префикса Ctrl-B
C-k        -                      # снять привязку: клавиша снова печатает символ
```

Имена клавиш: `C-x` (Ctrl), `Cmd-x`, `M-x` (Alt/Option), `S-` (Shift) для спецклавиш, сочетания `C-S-Left`; спецклавиши `Left Right Up Down Home End PgUp PgDn Ins Del Backspace Tab Enter Esc Space F1…F12`; `C-/` — Ctrl+/. Команды: `Keys` — все действующие привязки; `Keys actions` — все действия, которые можно назначить; `Keys file` — путь к файлу. Полное описание клавиш — `docs/03-keyboard-spec.md`. Пример `config/keys` содержит все привязки по умолчанию.

### `theme` — цвета

```
style keyword fg=#5f87af           # цвет стиля подсветки: fg=, bg=, line=, underline/nounderline
style comment fg=#7f7f7f
style variable -                   # убрать стиль: рисовать как обычный текст
text.back #fdf6e3                  # цвет окна (слот палитры), применяется после перезапуска
tag.back #eee8d5
```

Файл накладывается на выбранную палитру. Палитру лучше выбирать в `config`; строка `palette ИМЯ` в `theme` тоже работает, но `config` и `-palette` её перекрывают. Цвета: `#rgb`, `#rrggbb`, `#rrggbbaa`. Слоты палитры: `tag.*` и `text.*` (`back high bord text htext tick`), `ui.modbutton ui.colbutton ui.but2 ui.but3`; после цвета можно указать `mix #ffffff` — смесь 50/50. Имена стилей подсветки: `comment keyword string number type function constant preproc heading emphasis link variable operator punctuation error warning info hint match diff.add diff.del diff.change`; имя с точкой (`error.syntax`) без своего цвета берёт цвет имени до точки. Команды: `Theme` — текущие стили в синтаксисе файла; `Theme slots` — список слотов; `Theme file` — путь. В примере `config/theme` все строки закомментированы: это цвета `doom-light` для справки.

### `fmt` — форматирование при сохранении

```
.go   gofmt -s                        # суффикс или точное имя файла, затем команда
.ts   prettier --stdin-filepath %f    # %f — путь к файлу
Makefile -                            # снять правило
put off                               # не форматировать при Put; команда Fmt работает
```

Команды: `Fmt` — отформатировать окно сейчас; `Fmt rules` — правила; `Fmt file` — путь. Подробно — `docs/07-format-spec.md`.

## Что задано в коде

Если файла нет или в нём нет нужной строки, действует значение из кода:

- **Общие настройки** — таблица `settingDefs` в `editor/settings.go`.
- **Клавиши** — таблицы в `editor/keys.go` (`defaultBindings`), `editor/keysmod.go` (клавиши с модификаторами) и `editor/prefix.go` (после Ctrl-B).
- **Палитры** — шесть встроенных: `doom-light` (светлая, мягкая; **по умолчанию**) и `doom-dark` (тёмная, по мотивам doom-one) в `editor/theme/doom.go`; `acme` (жёлтая, как в оригинальном Acme), `vampira` (тёмная), `solarizedlight`, `solarizeddark` в `editor/theme/palette.go`. Отдельных файлов тем пока нет. Как подобраны цвета — `docs/10-theme-style-guide.md`.
- **Цвета подсветки** для каждой палитры — рядом с палитрой (`doom.go`, `styles.go`).
- **Форматирование** — одно правило: `.go gofmt`, в `editor/fmtfile.go`.

Примеры в `config/` проверяются тестами: если умолчание в коде поменяется, а пример нет, тест упадёт.

## Флаги запуска

Флаги задаются в командной строке редактора; `run.sh` передаёт свои аргументы дальше, поэтому `./run.sh -palette doom-dark файлы` работает. Флаг перекрывает и `config`, и умолчания.

| Флаг | Что задаёт |
|---|---|
| `-f шрифт`, `-F шрифт` | пропорциональный и моноширинный шрифт |
| `-palette имя` | палитра |
| `-W 1600x1000@X,Y` | размер и положение окна |
| `-c N` | число колонок при запуске |
| `-a` | автоотступ во всех окнах |
| `-b=false` | фокус под мышью, как в Acme |
| `-r` | поменять местами кнопки прокрутки |
| `-l файл` | восстановить окна из дампа (дамп хранит и шрифты) |
| `-m путь` | точка монтирования 9P |

## Переменные окружения

| Переменная | Что задаёт |
|---|---|
| `DOOMCODE_CONFIG`, `DOOMCODE_KEYS`, `DOOMCODE_THEME`, `DOOMCODE_FMT` | путь к файлу настроек вместо `~/.config/doomcode/…` |
| `XDG_CONFIG_HOME` | каталог настроек: `$XDG_CONFIG_HOME/doomcode` |
| `tabstop`, `tabexpand` | как одноимённые настройки в `config`; переменная побеждает |
| `acmeshell` | оболочка для команд (по умолчанию `rc` из plan9port) |
| `mousescrollsize` | шаг прокрутки колесом |
| `NAMESPACE` | каталог сервиса 9P; `run.sh` ставит `/tmp/ns.doomcode`, чтобы не мешать plan9port acme. Путь должен быть коротким: в нём создаётся Unix-сокет, а длина его имени ограничена (около 100 символов) |

## Другие файлы

- **`~/doomcode.dump`** — раскладка окон, которую пишет команда `Dump` и читает `Load` (или флаг `-l`).
- **`run.sh`** в корне репозитория — запуск с нужным окружением: путь к devdraw, `NAMESPACE`, `~/go/bin` в `PATH` (там `L` из acme-lsp). Шрифты он не задаёт: они берутся из `config` или палитры. Свои флаги удобно дописывать в вызов `run.sh`.

## Как начать настраивать

1. Нажмите **Cmd-,** (или выполните `Config`) — откроется каталог настроек.
2. Выполните `Config init` — в каталоге появятся `config`, `keys`, `theme`, `fmt` со всеми умолчаниями и комментариями.
3. Откройте нужный файл (Ctrl-O на имени), поменяйте строку, сохраните (Ctrl-S).
4. Выполните `Config reload` — изменения применятся (палитра, шрифты и размер окна — после перезапуска).
5. Чтобы вернуть файл к умолчаниям: `Config reset ИМЯ` (старый останется как `ИМЯ.bak`).
